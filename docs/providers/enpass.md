# Enpass

Read secrets from a local Enpass vault directory (`.enpassdb`), supporting Enpass 6 format with SQLCipher v3/v4.

## Quick Start

```bash
# 1. Set vault password
export FNOX_ENPASS_PASSWORD="your-master-password"

# 2. Configure provider
cat >> fnox.toml << 'EOF'
[providers]
enpass = { type = "enpass", vault_path = "~/Documents/Enpass/Vaults/primary" }
EOF

# 3. Define secrets
cat >> fnox.toml << 'EOF'
[secrets]
DATABASE_URL = { provider = "enpass", value = "database-url" }
EOF

# 4. Retrieve secret
fnox get DATABASE_URL
```

## Configuration

```toml
[providers]
enpass = { type = "enpass", vault_path = "~/Documents/Enpass/Vaults/primary" }

# OR with keyfile for additional security
enpass = { type = "enpass", vault_path = "~/Documents/Enpass/Vaults/primary", keyfile = "~/keyfile.xml" }
```

### Vault Path

The `vault_path` field points to the Enpass vault directory containing `vault.enpassdb` and `vault.json`. Shell expansion is supported:

```toml
[providers]
enpass = { vault_path = "~/Documents/Enpass/Vaults/primary" }  # Home directory
enpass = { vault_path = "/opt/secrets/enpass-vault" }          # Absolute path
```

### Keyfile (Optional)

If your vault uses a keyfile, specify it in the config:

```toml
[providers]
enpass = { vault_path = "~/vault", keyfile = "~/keyfile.xml" }
```

The keyfile is an XML file containing hex-encoded key bytes, as generated by Enpass.

## Authentication

Set the vault password via environment variable:

- `FNOX_ENPASS_PASSWORD` (preferred)
- `ENPASS_PASSWORD` (fallback)

```bash
# Recommended: FNOX_ENPASS_PASSWORD
export FNOX_ENPASS_PASSWORD="your-master-password"

# Alternative: ENPASS_PASSWORD
export ENPASS_PASSWORD="your-master-password"
```

::: warning
Do not store the password directly in config files. Use environment variables for security.
:::

## Reference Formats

Enpass references use the item title and optionally a field label:

| Format           | Example             | Description                          |
| ---------------- | ------------------- | ------------------------------------ |
| Item title       | `my-login`          | Returns the password/sensitive field |
| Item title/field | `my-login/username` | Returns the specific field by label  |

### Simple Item Title

```toml
[secrets]
DATABASE_URL = { provider = "enpass", value = "database-url" }
```

Searches for an item with this title and returns its password (sensitive) field.

### Item with Field

```toml
[secrets]
DB_USER = { provider = "enpass", value = "database/username" }
DB_PASS = { provider = "enpass", value = "database/password" }
DB_URL = { provider = "enpass", value = "database/url" }
```

## Filtering

When multiple Enpass items share the same title, use the `filter` field to disambiguate by metadata such as tags, category, or other item properties.

### Filter by Tag

Enpass tags (stored as folders internally) can be matched with the `tag` key:

```toml
[secrets]
# Single tag
DB_DEV = { provider = "enpass", value = "Database/password", filter = { tag = "DEV" } }

# Multiple tags (AND — item must have ALL listed tags)
DB_STAGING = { provider = "enpass", value = "Database/password", filter = { tag = ["staging", "backend"] } }
```

The aliases `tags` and `folder` also work for the `tag` key.

### Filter by Category

Match the Enpass built-in category (e.g., `login`, `creditcard`, `note`):

```toml
[secrets]
DB_PASS = { provider = "enpass", value = "Database/password", filter = { category = "login" } }
```

### Filter by Favorite / Archived

```toml
[secrets]
FAV_SECRET = { provider = "enpass", value = "My Secret/password", filter = { favorite = "true" } }
ARCHIVED = { provider = "enpass", value = "Old Secret/password", filter = { archived = "true" } }
```

### Combining Filters

All filter conditions are combined with AND:

```toml
[secrets]
# Must be tagged "PROD" AND category "login"
PROD_DB = { provider = "enpass", value = "Database/password", filter = { tag = "PROD", category = "login" } }

# Must have both tags AND be a favorite
SPECIAL = { provider = "enpass", value = "API Key/password", filter = { tag = ["backend", "prod"], favorite = "true" } }
```

### Filter by Entry Field

When built-in filters aren't enough, you can match against any field stored in the entry. This is useful when multiple entries share the same title but differ in fields like Username, URL, or Email:

```toml
[secrets]
# Filter by Username field
DB_ADMIN = { provider = "enpass", value = "Database/password", filter = { Username = "admin" } }
DB_READONLY = { provider = "enpass", value = "Database/password", filter = { Username = "readonly" } }

# Filter by URL field
PROD_API = { provider = "enpass", value = "API Key/password", filter = { URL = "https://api.prod.example.com" } }
DEV_API = { provider = "enpass", value = "API Key/password", filter = { URL = "https://api.dev.example.com" } }

# Combine with other filters
PROD_DB = { provider = "enpass", value = "Database/password", filter = { Username = "deploy", tag = "PROD" } }
```

Field names are matched case-insensitively against the entry's field labels. Values are also compared case-insensitively. Sensitive (encrypted) fields are decrypted before comparison.

### Ambiguity Error

If multiple items still match after filtering, fnox returns an error listing all candidates with their tags and categories so you can refine the filter.

## How It Works

1. **Vault format:** Enpass vaults are SQLCipher-encrypted SQLite databases
2. **Key derivation:** PBKDF2-HMAC-SHA512 derives the database key from the master password
3. **Database encryption:** SQLCipher (AES-256-CBC) protects the entire database
4. **Field encryption:** Sensitive fields use AES-256-GCM with per-item keys
5. **Config:** `fnox.toml` stores only the item title reference, not the actual secret

### Decryption Flow

```
vault.json → Read KDF parameters (iterations, algorithm)
vault.enpassdb → Extract 16-byte salt from file header
Master password + salt → PBKDF2-HMAC-SHA512 → Database key
Database key → Open SQLCipher database
Query item + itemfield tables → Decrypt sensitive fields with AES-256-GCM
```

## Example Configurations

### Personal Vault

```toml
[providers]
enpass = { type = "enpass", vault_path = "~/Documents/Enpass/Vaults/primary" }

[secrets]
GITHUB_TOKEN = { provider = "enpass", value = "GitHub/password" }
NPM_TOKEN = { provider = "enpass", value = "npm/password" }
AWS_SECRET = { provider = "enpass", value = "AWS Console/password" }
```

### With Keyfile

```toml
[providers]
enpass = { type = "enpass", vault_path = "~/vault", keyfile = "~/enpass-keyfile.xml" }

[secrets]
MASTER_KEY = { provider = "enpass", value = "master-key" }
```

### Multiple Vaults

```toml
[providers]
personal = { type = "enpass", vault_path = "~/Enpass/personal" }
work = { type = "enpass", vault_path = "~/Enpass/work" }

[secrets]
PERSONAL_TOKEN = { provider = "personal", value = "github-token" }
WORK_API_KEY = { provider = "work", value = "company-api" }
```

## Pros

- ✅ Local-first - no cloud dependency
- ✅ Read-only access - cannot modify vault
- ✅ Supports SQLCipher v3 and v4 (Enpass 6.8+)
- ✅ Works offline
- ✅ Per-item encryption keys (AES-256-GCM)
- ✅ Batch fetching - opens database once for multiple secrets
- ✅ Optional keyfile support

## Cons

- ❌ Read-only - cannot create or update items via fnox
- ❌ Requires master password in environment
- ❌ No built-in sync (Enpass handles sync separately)
- ❌ No audit logs
- ❌ Vault directory must be accessible locally

## Supported Versions

- Enpass 6.x (SQLCipher v3)
- Enpass 6.8+ (SQLCipher v4, tried first)

## Troubleshooting

### "Vault password not set"

Set the password environment variable:

```bash
export FNOX_ENPASS_PASSWORD="your-master-password"
# or
export ENPASS_PASSWORD="your-master-password"
```

### "Could not open vault database: invalid password or unsupported version"

Verify:

1. Password is correct
2. Vault directory contains both `vault.enpassdb` and `vault.json`
3. Keyfile is configured if the vault requires one

### "Item not found"

Check that:

1. The item title matches exactly (case-insensitive)
2. The item is not in the trash
3. The item has not been deleted

### "Vault requires a keyfile but none was configured"

Your vault was created with a keyfile. Add it to your config:

```toml
[providers]
enpass = { type = "enpass", vault_path = "~/vault", keyfile = "~/keyfile.xml" }
```

## Security

- **Database encryption:** SQLCipher AES-256-CBC with PBKDF2-HMAC-SHA512 key derivation
- **Field encryption:** AES-256-GCM with per-item keys and UUID-based AAD
- **Key derivation:** 100,000+ PBKDF2 iterations (configurable per vault)
- **Read-only:** fnox never modifies the vault database
